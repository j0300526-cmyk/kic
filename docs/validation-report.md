## 최종 테스트 실행

의존성이 설치된 깨끗한 소스 상태에서 다음 명령을 실행했습니다.

```text
backend> python -m pytest -q
....................... [100%]
23개 통과

frontend> npm test
테스트 파일  4개 통과
테스트       8개 통과

frontend> npm run build
TypeScript 프로젝트 및 Vite 프로덕션 빌드 성공
```

HTTP 스모크 테스트 확인 사항:

- 여섯 Agent 분석과 승인된 Critic 결과
- 수치 허용오차 안의 포트폴리오 비중 합계
- 기본 균형과 가치평가 중심 믹스 사이 최대 6.26%p 배분 차이
- SQLite 시나리오 생성 및 조회
- 전 가중치 0 입력에 대한 고정 `ZERO_AGENT_WEIGHT` 오류

로컬 Chrome에서 실제 FastAPI 연결 상태로 종합 현황, Agent 믹싱 콘솔,
포트폴리오 최적화 화면을 각각 1600px 너비로 렌더링해 시각 검수했습니다.
컴포넌트 상호작용 테스트, 프로덕션 렌더링 컴파일, 프론트엔드 HTTP 200,
전체 API 데이터 경로도 함께 검증했습니다.

## 기관 운용 터미널 UI 재검증

바이낸스형 인터페이스의 장점인 높은 정보 밀도, 상시 시장 티커, 빠른 상태
식별 방식을 차용하되 거래소 화면을 복제하지 않고 TPA 의사결정 흐름에 맞게
재구성했습니다. Agent 원시 가중치와 정규화 반영률을 분리해 표시하며, 최종
반영률 합계는 항상 100%입니다.

실제 API에 기본 균형 믹스와 가치평가 중심 믹스를 연속 요청한 결과:

- 두 요청 모두 정규화 Agent 가중치 합계 `1.0`
- 두 요청 모두 최종 포트폴리오 비중 합계 `1.0`
- 미국 주식 `16.53% → 23.74%`로 `+7.21%p`
- 미국 국채 `39.01% → 32.75%`로 `-6.26%p`

종합 현황, 믹싱 콘솔, 포트폴리오 최적화 화면을 실제 FastAPI 연결 상태에서
다시 캡처했으며 차트, 한글 레이블, 상태 배지, 제약 표시를 육안 검수했습니다.

## Yahoo Finance 지연 시세 검증

`GET /api/v1/market/snapshot`에서 S&P 500, 미국 10년물 금리, 금 선물,
달러지수 네 종목을 실제 조회했습니다. 전일 종가는 Yahoo의 5일 차트 기준값이
아니라 일별 종가 배열에서 직전 거래일 값을 선택하도록 검증했습니다.

- provider `yahoo_finance`, status `delayed`, HTTP 200 확인
- S&P 500 `7,580.07`, 일간 `-1.82%`
- 미국 10년물 `4.929%`, 일간 `-6.0bp`
- 금 선물 `$3,898.90`, 일간 `-3.29%`
- 달러지수 `101.96`, 일간 `+0.08%`
- 두 번째 요청은 60초 메모리 캐시 사용
- 외부 연결 실패 시 마지막 정상값, 정상값이 없으면 명시적 sample fallback

시장별 제공 시점이 다르므로 화면은 가장 최근 시각과 함께 `Yahoo Finance ·
지연 시세`를 표시하며 투자 실행 가격으로 오인할 수 있는 실시간 표현을 사용하지
않습니다.

## 글로벌 리스크 지도 검증

`GET /api/v1/risk/events?window=24h`의 기사 정규화, 중복 제거, 이벤트 분류,
지역 매핑, Agent·자산 영향 스키마를 자동 테스트했습니다. 지도 마커의 키보드
접근성과 선택 이벤트를 믹싱 동작으로 전달하는 상호작용도 Vitest로 검증했습니다.

- 외부 응답 성공: `provider=gdelt`, `status=live`, 이벤트별 `data_mode=live`
- 호출 제한·연결 실패: `provider=mock`, `status=fallback`, 이벤트별 `data_mode=mock`
- fallback은 실제 뉴스로 오인하지 않도록 화면 상단 경고와 이벤트 배지를 표시
- 위치가 식별된 이벤트만 지도에 표시하고 전체 기사 스트림은 별도로 유지
- 자동 분류·위치·영향 추정은 원문과 구분하고 교차 확인 경고를 상시 표시
